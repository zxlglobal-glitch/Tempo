# Tempo

Социальное фитнес-приложение: Next.js App Router, TypeScript, React и Supabase.

## Запуск

Требуется Node.js 22+ и pnpm.

```sh
pnpm install --frozen-lockfile
cp .env.example .env.local
pnpm dev
```

Откройте http://localhost:3000. Без переменных окружения можно просмотреть интерфейс; запись и авторизация отключены.

## Подключение Supabase

1. Создайте проект Supabase. Текущий `supabase/schema.sql` предназначен для существующей базы с таблицей profiles и bucket avatars. Он создаёт workouts, индексы, RLS и публичный bucket photos, не изменяя profiles и avatars. Для подключённого проекта миграция уже применена.
2. В `.env.local` укажите URL проекта и **publishable** key из Connect/API Keys. Secret key и service_role не нужны. `.env.local` исключён из Git.
3. В Authentication включите Email/Password. Для подтверждения email задайте Site URL `http://localhost:3000` и разрешённый Redirect URL `http://localhost:3000`. Для размещённого приложения добавьте его адрес.
4. Перезапустите сервер. Зарегистрируйтесь, подтвердите email, войдите и заполните профиль.

## Структура и поведение

- `src/app` — Next.js, маршруты и адаптивные стили.
- `src/components/tempo.tsx` — лента, авторизация, создание тренировки, профили.
- `src/lib/supabase.ts` — клиент Supabase, типы и загрузка фотографий.
- `/`, `/login`, `/register`, `/workouts/new`, `/profile/edit`, `/people/<uuid>`.
- Все 9 категорий; фильтрация и загрузка ленты порциями по 20 записей.
- До 6 фото на тренировку, до 5 МБ каждое: JPEG/PNG/WebP.
- Профиль создаётся существующим триггером Supabase при регистрации. Клиент передаёт display_name в metadata и изменяет существующий профиль через UPDATE; INSERT/upsert из браузера не используется. Сессия управляется браузерным SDK Supabase; защита данных обеспечивается RLS, а не редиректами интерфейса.
- Тренировки и фото публичны. По текущим policies profiles доступны только authenticated: гости видят тренировки без данных авторов, после входа — полную ленту. Аватары используют avatars, фотографии тренировок — photos; пути имеют вид <user_uuid>/<unique_filename>. Поле «О себе» ограничено 500 символами. Email не хранится в публичном профиле. Запись разрешена только владельцу. При ошибке публикации загруженные файлы удаляются по возможности.
- Личные сообщения пока обозначены как «Скоро». Для них потребуется отдельная модель диалогов, участников и приватные политики.

## Проверки

```sh
pnpm typecheck
pnpm test:db
pnpm build
pnpm start
```

`test:db` исполняет схему в PGlite (PostgreSQL) с минимальной имитацией служебных схем Supabase. Проверяет RLS для двух пользователей, публичное чтение, запрет чужих записей/файлов, категории и лимит фото. Это не заменяет проверку настоящих сервисов Auth, email и Storage.

После подключения настоящего проекта проверьте регистрацию с подтверждением email, вход/выход, сохранение профиля и аватара, публикацию 2 фото, фильтры и профиль другого пользователя. С двумя аккаунтами убедитесь, что изменение чужого профиля и загрузка в чужую папку запрещены. Также проверьте запрет более 6 фотографий, файлов больше 5 МБ и неподдерживаемых форматов.

Очистка старых аватаров, модерация и личные сообщения пока не реализованы.

Read-only проверка реального API: `node tests/live-readonly.mjs`. Она читает ленту и настройки Email Auth, не создавая данные. Полный тест регистрации требует подтверждения email и тестового входа.

## Тренировки, лайки и комментарии

- `/workouts/<uuid>` открывает тренировку; `/workouts/<uuid>/edit` доступен её владельцу.
- Кнопки редактирования/удаления есть на своей карточке и странице тренировки. Удаление требует подтверждения. Окончательные права проверяются существующими RLS workouts.
- При редактировании суммарно допускается до 6 сохранённых и новых фото. Убранные фото удаляются после успешного UPDATE. При удалении тренировки сначала выполняется DELETE записи, затем удаляются её фото. Ошибки очистки Storage показываются отдельно; межсервисной транзакции между Postgres и Storage нет.
- Новая миграция: `supabase/workout_social.sql`. Она подготовлена для ручного просмотра и применения; автоматически НЕ выполнялась. Existing profiles, workouts, avatars, photos и их policies не меняются.
- После применения миграции доступны переключение лайка, точные счётчики, комментарии до 1000 символов и удаление своего комментария. Пока таблиц нет, тренировки остаются доступны, социальные элементы показывают сообщение о недоступности.
- Комментарии идут по времени, загружаются порциями по 50. Счётчики используют точный COUNT базы, а не размер первой страницы.
- Текущие profiles policies разрешают чтение только вошедшим: для гостей тренировки и комментарии доступны, но автор показан как «Участник». Политики profiles намеренно не расширены.

Проверки без подключения к рабочей базе:

```sh
node --test tests/workout-photos.mjs tests/workout-mutations.mjs
node tests/schema.mjs
node tests/social-schema.mjs
```

SQL-тесты используют отдельный PostgreSQL в памяти (PGlite). Проверены повторное применение миграции, уникальность лайков, права двух пользователей, каскадное удаление, ограничения комментариев и сохранение прежних данных. Тесты файлов моделируют ошибки Storage. Полный браузерный тест с двумя аккаунтами следует выполнить после ручного применения новой миграции.
